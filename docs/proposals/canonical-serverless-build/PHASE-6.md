# Phase 6: a guest without a toolchain, verification record

Machine: Windows 11 Home 10.0.26200, Node v22.21.0, x64; rustc 1.97.1 for the one build of the evaluator guest. Browsers: Chromium 141, Firefox 142 and WebKit 26, headless under Playwright 1.65, on the same machine.

Each entry is one kind of claim: proved, tested or measured. Nothing here is proved by Lean beyond what a model's own theorems state.

## The three options, and the one taken

The proposal asked for three options to be measured: LexLean emits WebAssembly; a pinned guest built by the user's Actions; a prebuilt guest per model shape.

Taken: one prebuilt guest for every text application. It is an evaluator; the model's program, written from its `lexlean/semantic-snapshot/2`, is attached to it as one data segment. Nothing is compiled for an app, so no Actions run and no toolchain is in the author's loop.

Not taken:

- A guest built by the user's Actions. It keeps minutes of waiting and a second place to trust. It stays the route for server apps, the binary profile and native command-line builds.
- LexLean emitting WebAssembly per app. It would give faster guests. It needs a compiler whose correctness would have to be stated against a WebAssembly semantics. Left open; the evaluator's speed has not been a limit for text applications.

## What was found on the way

- For a text application, the Rust the SDK image compiles is generated by lean4-prod's `prod-codegen` from Lean's compiler output (`crates/prismpm/src/application_build.rs`). LexLean's certified compiler is used for server apps only (`crates/prismpm/src/server_build.rs`). So the step from model to guest was tested, not proved, before this change, and is tested, not proved, after it.
- The package's own holo reader (`src/archive.mjs`, `resolveArchiveV5`) requires of a provenance object its schema name, the guest, model and view labels and the application label. It requires no Cargo crate hash and no browser adapter hash. A holo without them verifies.

## Tested

`test/model-eval.test.mjs`, 9: the reference evaluator runs a snapshot's own definitions. A decision app answers 27 of 27 of its acceptance vectors and a stateful app 37 of 37, a 1,024-byte session among them. Planted defects refused: a primitive that answers otherwise; a changed constant.

`test/model-guest.test.mjs`, 10: the linked guest imports nothing and exports exactly `memory`, `holo_alloc` and `holo_run`; it answers as the reference evaluator on each app's vectors and on requests made from them; the same model gives the same bytes. Planted defects refused: one changed word of the program; a guest that is not the pinned one; a model that uses what the guest does not run, by name.

`test/model-guest-primitives.test.mjs`, 13: every primitive at the edges of every type, more than 3,000 cases. For each, the reference computes the answer and the guest is asked whether its own equals it. A planted wrong answer is seen by both. A number past 127 bits is refused by name as a literal and traps as a result.

`test/model-holo.test.mjs`, 10: the holo verifies in the package's own loader and answers its vectors; the page is byte for byte the page in `fixtures/PaymentApproval.v5.holo`, which the SDK image built. Planted defects refused: a flipped byte; a guest or a model document changed and sealed again; a model with no vectors; an example the rules do not answer.

`test/model-bundle.test.mjs`, 4, and `test/model-site.test.mjs`, 2: the holo travels in the app bundle under its BLAKE3 label and is published with its model beside it. Planted defect refused: one changed byte of a pushed holo.

`test/browser/run.mjs`, run by hand: in a worker, each of the three browsers checks a starter, takes its snapshot and builds its holo. Each must name it by the label Node gives.

## Limits

- That the guest follows the model is tested, not proved. Stating the evaluator and proving it against LexLean's target semantics is not done.
- The guest holds numbers up to 127 bits. Past that it refuses or traps; it does not answer.
- Maps, sets, folds, bounded iteration, graphs, lambdas and decimal text are not run, by the reference or by the guest. A model that uses one is refused by name with `build.guest-uncovered`.
- The provenance object keeps the name `prismpm/model-provenance/2` and carries `builder` in place of the Cargo fields, because the reader requires that name. A schema revision is owed. Measured with the Rust reader (`prismpm`, built on Linux from this branch) on the loan app's holo: `prismpm inspect` reads it (7 sections, `hologram:guest/core-wasm@1`, conforming), and `prismpm check` refuses the provenance object under `holo.documents` for the unknown field `builder`. The level is P0 either way: the holo carries no provenance, proof or replay statement, as the SDK image's `fixtures/PaymentApproval.v5.holo` does not, and that fixture is P0 as well.
- The evaluator guest's source contains `unsafe`: its allocator, and reads of its own memory. It is outside `crates/`, which is what the repository's audit covers.
- WebKit under Playwright is not Safari. No phone was measured.
